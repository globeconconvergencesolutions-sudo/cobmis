# Decisions log

Non-obvious choices and why. Newest at the bottom.

**D-001 Repo root is the `cob-agent/` root from PLAN.md.** The repo is `cobmis`; the plan's layout is applied directly at the root rather than nesting another folder.

**D-002 Postgres runs on host port 5433, not 5432.** Avoids clashing with a native Postgres many dev machines already run. Configurable via `POSTGRES_PORT`. Bound to `127.0.0.1` only.

**D-003 Three DB login roles created at init (`db/init/10_roles.sh`).**
`cob_app` (API), `cob_ingest` (only writer of corpus/structured data), `cob_readonly` (text-to-SQL executor). `cob_readonly` has `default_transaction_read_only=on`, `statement_timeout=10s`, and USAGE on `public_data` only; no access to `private` until a collection grant is issued. Per-table grants come with the migrations that create tables. Defence in depth on top of sqlglot validation (Phase 4).

**D-004 Model tags are placeholders until verified on the target host.** *(Updated 2026-10-21: the owner confirmed `qwen3.5:9b` (Q4_K_M, 6.6 GB) and `bge-m3` are pulled and working on the target machine; the `small` profile now uses exactly those. Medium/large tags remain unverified.)* The build sandbox cannot reach `registry.ollama.ai` or `ollama.com`, so tags in `config.yaml` (`qwen3.5:9b`, `qwen3.6:27b`, `qwen3.6:35b-a3b`, `qwen3-coder:30b`, `bge-m3`, `nomic-embed-text`) come from 2026 secondary sources and must be confirmed with `ollama pull` + `scripts/check_ollama.py` before Phase 3. Final choice waits on the owner's hardware specs.

**D-005 `think: false` on every chat call.** Qwen 3.x tags enable thinking by default. For routing, SQL generation and grounded answers we want short deterministic output; thinking adds latency and can leak reasoning into answers. Revisit per-task if SQL accuracy benefits from it.

**D-006 Loopback is enforced in code, not just in config.** `Settings` refuses to start if the Ollama URL, DB host or API host is not a loopback address. This makes "accidentally pointed at a remote/hosted endpoint" a startup error. The Ollama HTTP client also sets `trust_env=False` so a system `HTTP(S)_PROXY` can never relay model traffic off-box.

**D-007 Separate `content` schema for documents and chunks.** The plan lists `documents`/`chunks` without a schema. Keeping them out of `public_data` means the text-to-SQL role never sees raw chunk text (including restricted-collection chunks) by schema permission alone.

**D-008 Embedding dimension is checked on every embed call.** A mismatch between the model and `embed_dim` (and so the `vector(N)` column) fails loudly instead of corrupting the index.

**D-009 `/health` returns 503 when degraded.** Lets scripts and the admin UI treat it as a readiness probe.

**D-010 `num_ctx` on every Ollama call, `think: false` on every chat call (owner requirement).** Ollama's default context window (4K on many builds) silently truncates long RAG prompts, so the client always sends `options.num_ctx` from the profile (8192 for `small`), including on `/api/embed`. A unit test inspects every request payload to enforce both settings.

**D-011 Scraper design (Phase 1).**
- *Not yet validated against the live page.* Neither the build sandbox's proxy nor the web-fetch tool could reach `cob.go.ke` during Phase 1, so the listing parser is built from the structure described in PLAN.md §1 and common WordPress Download Manager markup, and tested against a clearly labelled synthetic fixture. Every live run saves `data/listing_snapshot.html`; that snapshot should replace the synthetic fixture as the regression test.
- Listing parsing is layout-tolerant: any same-site `/download/<slug>/` link inside the main content, with the FY taken from the title, then the slug, then the nearest FY heading above it (noted in `parse_notes`).
- Periods are cumulative in COB reports, so "Third Quarter" maps to `9M` and "Fourth Quarter" to `FY`. Unrecognised periods are kept as `null` with a note, not guessed.
- A `/download/<slug>/` URL that redirects straight to a PDF is saved from that first response (one request). Otherwise the package page is searched for `data-downloadurl`, `?wpdmdl=`, `.pdf` hrefs and `onclick` URLs. Playwright is not used unless a live run shows plain HTTP is not enough.
- Status meanings: `unavailable` = listed as 0 KB with no file, HTTP 404/410, or no file link (skipped on reruns unless `--retry-unavailable`); `failed` = transient or bad content (retried on every rerun); `scanned` = downloaded but <50% of sampled pages have a text layer (OCR in Phase 2).
- robots.txt: honoured, including `Crawl-delay`. A 401/403 robots.txt is treated as "disallow all" (Python stdlib convention); an unreachable one falls back to the 2–3 s delay.
- Downloads are written unbuffered to `.part` so an interrupted transfer keeps what arrived and resumes with HTTP `Range`.

**D-012 PyMuPDF (AGPL-3.0) is acceptable.** This is a private, non-distributed deployment. If the system is ever offered as a network service to third parties, revisit (AGPL network clause) or swap in pdfplumber/pypdfium2.

**D-013 PDF parsing: PyMuPDF ruling-line grid, cells filled with whole words (Phase 2).** The FY 2025/26 reports are InDesign PDFs with a full text layer (text_page_ratio ≈ 0.98). PyMuPDF's `find_tables(strategy="lines")` finds the tables' ruled grids reliably (~0.5 s/page), but its own cell text drops word spaces ("TransNzoia") and splits figures ("5,793.60" → "579360\n, ."). Cell text is therefore rebuilt from glyph positions: glyphs → lines (by baseline) → words (by horizontal gap, since these PDFs have no space glyphs) → each *word* goes to the cell containing its centre. Word-level (not glyph-level) assignment matters because some tables' ruling lines are drawn offset from the text; glyph-level assignment split "865,750,217" into "865,750,2" | "17". The running title and page number (bottom 50 pt) are stripped; table text is excluded from narrative text. Pages are parsed in parallel batches of 25; each batch is written atomically, so a stopped parse resumes at the next missing batch, and `PARSE_VERSION` invalidates stale batches. Docling was not needed.

**D-014 Tables are identified by caption title, never by number.** Numbering differs between reports: "Table 2.4" is the absorption table in the H1 report and the economic-classification table in the annual report. Columns are mapped to metrics from their full header text (group headers carried over merged cells), not position. Tables continued on the next page (no caption, same column count or same header) are merged into one logical table that keeps the PDF page of every row.

**D-015 Structured schema (public_data), designed from the extracted chapter-2 tables.** One long fact table `fact_county_budget(county, period, metric, value, source_doc_id, source_page, source_table, source_row, printed_value, printed_unit)` plus `dim_county` (47, official codes, former province), `dim_period` (FY + Q1/H1/9M/FY, months, period end), `dim_metric` (26 metrics, unit, cumulative flag) and `source_document`. Amounts are stored in KES (converted from the printed "Kshs. Million"); the printed cell text and unit are kept beside every value. `v_county_metrics` is the friendly view for the SQL agent. Loaded tables: own-source revenue, economic classification, budget/expenditure/absorption, trade payables (pending bills), and the annual-only exchequer table. In these tables "-" means nil (loaded as 0, printed "-" kept); "n/a" is not applicable (cell skipped).

**D-016 Validation policy.** Row level: county name must resolve; every printed formula ("C=A+B", "G=D/A 100") must hold; values must parse. A failing row goes to `quarantine_rows` with the reason and is not loaded. Table level (47 counties, Total row = column sums, all expected columns mapped): recorded in `validation_results`; rows are still loaded. Same metric in two tables of one report (e.g. expenditure in the absorption and economic-classification tables): first value kept, agreement recorded (564/564 agree). Cross-period: year-to-date metrics must not fall H1 → 9M → FY; violations are flagged, not quarantined, because each value is correct *as printed*. Formula rows that are wrong in the source (a letter defined twice; a "%" column labelled with a variance formula) are skipped with a note rather than failing every row. A dash or blank *result* cell is "not computed", never zero.

**D-017 Scope of SQL normalisation in Phase 2.** Only the all-county chapter-2 tables are normalised. The ~15 per-county table types in chapter 3 (revenue streams, departments, established funds, projects...) are kept as whole-table chunks for retrieval and are arithmetic-checked, but not yet loaded into SQL. Their arithmetic failures are dominated by errors printed in the source (see the Phase 2 report), so they need quarantine-first handling when normalised in Phase 4.

**D-018 Plain SQL migrations instead of Alembic.** `db/migrations/NNN_*.sql`, applied in order by `scripts/migrate.py` (owner role), recorded in `app.schema_migrations`. Extensions, schemas and grants moved from the Docker init script into `000_base.sql` so a test database can be built the same way; the init script now only creates the three login roles. Alembic and the unused `pgvector` Python package were removed from requirements.

**D-019 Retrieval store.** `content.chunks` holds narrative and table chunks with `vector(1024)` (bge-m3; changing embedding size needs a migration and re-embed), an HNSW cosine index, and a generated English `tsvector`. Search fuses vector top-k and full-text top-k (OR of query terms) by reciprocal rank (k=60). The collection filter is inside the SQL. A county filter keeps all-county chunks too, so national context is not lost.

**D-020 Chunking.** Narrative: ~600 estimated tokens, ~12% sentence overlap, cut at headings and sentence ends; contents/list-of-tables lines (dot leaders), figure "Source:" notes and running titles inside charts are dropped. County comes from the "3.N County Government of X" heading, including headings that start mid-page (not from captions: the source has copy-paste errors such as "Karachi County" and "Nakuru County" captions inside the Kericho and Narok sections). Tables: one chunk per logical table, split only between rows (header repeated) above ~900 tokens. Context header, e.g. "County Governments Budget Implementation Review Report, FY 2025/26, First Nine Months, Kericho County, 3.12.19 General Observations and Recommendations", is stored and prepended before embedding.

**D-021 OCR deferred.** Only 14 of 2,651 pages are image-only (covers and "key highlights" infographics); they are flagged `needs_ocr` and skipped. Tesseract/OCRmyPDF are not installed yet; revisit when older, scanned reports are added.
